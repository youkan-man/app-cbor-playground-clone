# CBOR Workbench

セルフホストする CBOR Playground。cbor.me の基本的な変換・確認用途を、バイト探索、解析履歴、比較に拡張した独立実装です。コンパクトな日本語 UI と右クリック操作を中心にしています。外部サービスへのデータ送信や CDN はありません。

## 起動

```sh
git clone https://github.com/youkan-man/app-cbor-playground-clone.git
cd app-cbor-playground-clone
docker compose up -d --build
```

ブラウザーで `http://localhost:8080` を開きます。LAN 内では Docker ホストのアドレスを指定します。

ポートが使用中の場合は、リポジトリ直下の `.env` に `CBOR_PORT=8088` などを記述してください。`CBOR_MAX_BYTES=262144` で解析入力上限を変更できます。初期値は 256 KiB、ネスト上限は 128 です。

```sh
docker compose logs --tail=100 cbor
docker compose down
```

履歴は named volume `cbor-history` 内の SQLite に保存します。コンテナの更新・再起動・通常の `down` では保持されます。**`docker compose down -v` は履歴も削除します。**

> 認証機能はありません。接続ユーザーは同じ履歴を閲覧・変更できます。信頼する LAN 内で使用してください。インターネット公開には、認証と TLS を備えたリバースプロキシを別途用意してください。

## 画面と操作

- 左に検索可能な履歴、中央に入力と HEX / ASCII、右に解析ツリーと候補一覧を常時表示します。下部に比較を展開します。余白・行高を抑え、各ペイン境界はドラッグで変更できます。境界のダブルクリックで初期サイズ、フォーカス中の矢印キーでもサイズ変更できます。
- Hex・Base64・JSON・基本的な Diagnostic Notation から入力できます。ファイルの読込・ドロップにも対応します。`Ctrl / Cmd + Enter` で解析します。JSON / Diagnostic 入力は CBOR にエンコードして解析します。
- ツリーの選択とバイト範囲を相互に関連付けます。HEX 側はドラッグ、Shift + クリック、矢印キーで選択します。ツリーは検索・開閉、結果は Diagnostic / JSON に切り替えられます。
- **右クリック**で、値・表示値・Diagnostic・パス・HEX のみ・Base64 のコピー、選択部分の抽出と再解析、指定位置からの解析、履歴の名称変更・ピン留め・比較・削除などを行います。選択テキストに自動ポップアップは表示しません。`Shift + F10` でも対象のメニューを開けます。
- テーマはダーク / ライト。小さい画面では縦方向に配置し、履歴を開閉します。大きなツリー、バイト列、候補一覧は仮想スクロールします。

## 1 バイトごとの探索と順位

既定の「全オフセット探索」は、入力の **0 から末尾まで 1 バイト刻みの全開始位置**を検査します。1 候補は、その位置から始まる完全にデコード可能な CBOR 項目です。途中切れ・不正 UTF-8・不正な構造の項目を成功には数えません。

ヒット数は、正常に解析した CBOR 要素数です。コンテナー自身、配列要素、マップのキーと値、タグとその内容、不定長文字列の各チャンクを数えます。文字列・バイト列のペイロードを 1 バイトずつ別のヒットとして水増ししません。

順位は次の辞書式順序です。

1. ヒット数が多い。
2. 同数なら、解析したバイト数が多い。
3. さらに同数なら、トップレベルの項目数が多い。
4. 最後に開始オフセットが小さい。

最上位を自動表示し、全成功候補から手動切替できます。「全オフセット探索」をオフにすると開始位置を固定します。

**Sequence** をオンにすると、各開始位置から連続する複数の CBOR 項目を解析して合計します。最初の不正バイトでその候補を終了し、途中の不正バイトを飛び越えてヒットを追加しません。単一の CBOR 項目を含むフレームでは既定のオフ、CBOR Sequence ではオンを使用してください。

CBOR は整数 1 個など短いバイト列も有効なため、**最多ヒットは本来のパケット境界を保証しません**。候補の消費範囲、未解析の前後バイト、型・値も確認してください。探索ヒットなしの解析も履歴に残します。HEX などの入力形式自体が不正な場合は保存しません。

## 履歴と比較

解析のたびに、元バイト列・元入力・解析条件・候補順位・選択結果を SQLite に保存します。同じ入力の再実行も別履歴として保持し、勝手な件数制限や自動削除はしません。候補を変更した場合は、その履歴の選択結果を更新します。

任意の 2 件のチェックボックス、または履歴の右クリックから比較します。

| 比較 | 内容 |
| --- | --- |
| 構造・値 | キー / インデックスのパスで対応付け、追加・削除・値変更・符号化だけの変更を表示。マップのキー順変更だけでは値変更にしません。 |
| 解析範囲のバイト | 各履歴の選択した解析開始位置をそろえて左右比較。 |
| 入力全体のバイト | 絶対オフセットで元バイト列全体を比較。 |
| Diagnostic | 左右のテキストを行単位で併記し、同じ行位置の差を表示。挿入行の自動アラインメントではありません。 |

CBOR のエクスポートは未解析領域を含む**入力全体の元バイト列**です。選択要素だけの抽出はツリー / HEX の右クリックを使用します。Diagnostic エクスポートは選択結果、JSON エクスポートは履歴全体です。

## 対応範囲

RFC 8949 の基本型（整数、バイト列、UTF-8 文字列、配列、マップ、タグ、単純値、真偽値、null / undefined、半精度 / 単精度 / 倍精度浮動小数）と不定長形式を解析します。未知タグは保持しますが、個々のタグに固有の意味検証までは行いません。重複マップキーは失わずに表示し、警告します。

JSON にない値は `$integer`、`$bytes`、`$tag`、`$map`、`$simple`、`$undefined`、`$float` を使った表示用オブジェクトにします。64 ビット整数は文字列で精度を保持します。**これらは表示表現であり、JSON 入力で自動的に特殊型へ戻しません。** CBOR 固有型の入力には Diagnostic を使用してください。

Diagnostic は配列 / マップ、任意型のキー、タグ `24(...)`、`h'...'` / `b64'...'`、`simple(...)`、不定長配列 `[_ ...]` / マップ `{_ ...}` / 文字列 `(_ ...)`、基本的な数値幅指定に対応します。EDN の全拡張、cbor.me の全機能互換、決定的マップ整列を保証するものではありません。JSON / Diagnostic からの再エンコードは元のバイト表現と同一とは限らないため、バイト単位の保存には元 CBOR をエクスポートしてください。

HEX は連続表記、空白、`0x`、カンマ、コロン、`_`、`-` の区切りに対応します。オフセットや ASCII 欄付きダンプ全体は入力しないでください。Base64 は URL-safe・パディング省略にも対応します。

## 開発・テスト

Python 3.13 を使用します。フロントエンドはビルド不要の HTML / CSS / JavaScript です。

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python app.py
```

別ターミナルからブラウザーテストを実行できます。**テスト用インスタンスを使用してください。** テストデータを作成します。

```sh
playwright install chromium
python tests/browser_smoke.py --url http://localhost:8080 --output artifacts
```

ブラウザーからローカル HTTP を利用できない制限環境では、`--in-process` が同じ UI を ASGI TestClient に接続します。このモードは DOM 操作と API の結合テストであり、ブラウザーの HTTP 経路・CSP・Docker の検証ではありません。

初期実装では、ユニット / API / 実 HTTP 再起動テスト、RFC の例、不正入力、独立パーサーと 500 種類のランダム入力の全オフセット照合、Playwright の画面操作を確認しています。Docker CLI のない作業環境のため、**Docker イメージのビルド・コンテナ起動・利用先ホストへのデプロイは未検証**です。

仕様参照: [RFC 8949](https://www.rfc-editor.org/rfc/rfc8949.html)、[RFC 8742](https://www.rfc-editor.org/rfc/rfc8742.html)。
