操作と探索ルール


解析
データを入力して「解析する」、または Ctrl+Enter。解析ごとに履歴へ保存します。HEX / Base64 は復号し、JSON / Diagnostic はCBORへ変換して解析します。


全オフセット探索
0から入力の末尾まで1バイトずつ開始位置をずらし、各位置から1つのCBOR項目を解析します。「連続項目」を有効にすると、エラーになるまで連続する項目をまとめて評価します。途中の不正バイトは飛び越えません。
ヒット数は正常に解析できたCBOR要素の数です。配列・マップ・タグ自身、キー、値、ネストした要素、文字列のチャンクを含みます。文字列内の各バイトは数えません。ヒット数 → 解析バイト数 → トップレベル項目数 → 小さいオフセットの順で選択します。
候補をクリックすると、その位置の結果に切り替わり、選択状態も履歴に保存します。開始位置を指定するには「全オフセット探索」をオフにします。
探索は推定です。短い整数などは偶然一致しやすく、最多ヒットが実際の送信形式とは限りません。登録タグ固有の意味・妥当性までは検証しません。


要素・バイトの操作
要素を選択すると対応バイトを強調します。バイトから対応要素を選ぶこともできます。右クリック、Shift+F10、または「操作」「要素操作」「履歴の ⋯ 」で同じメニューを開けます。値・表示値・パス・HEXのコピーや、選択部分・バイト文字列の中身の再解析ができます。


履歴比較と画面配置
履歴の2件をチェックして「比較する」。構造・値・符号化、バイト、Diagnosticを比較できます。「比較を拡大」で比較専用の表示に切り替え、「解析と併記」で戻します。履歴のダブルクリックで固定、右クリックで名前変更や削除ができます。
ペインの境界をドラッグすると幅・高さを変更できます。境界をダブルクリックするとその境界だけ初期化、「配置を戻す」で全体を初期化します。境界にフォーカスして矢印キーでも調整できます。


対応表記と保存
Diagnosticは基本表記（タグ、h'…'、b64'…'、simple、NaN/Infinity、不定長、数値幅）に対応します。拡張表記の全機能やdCBORには対応していません。JSON出力の $bytes / $tag / $integer / $map 等は、JSON入力では通常のキーです。型を保って再入力するにはDiagnosticを使用してください。
履歴はDockerの名前付きボリューム内のSQLiteに保存されます。
